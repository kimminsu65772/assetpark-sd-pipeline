# 에이전트 안내 — 제작 페이지에서 "보냈어"를 들었을 때

**쉬운 요약**: 사용자가 제작 페이지에서 모델에 이상한 곳을 칠하고 "보내기"를 누르면 파일이 하나 생깁니다. 사용자가 Claude 앱에서 "보냈어"라고 하면, 에이전트는 아래 명령으로 그 파일을 받아 고치고, 항목마다 "고침 / 안 고침 + 이유"를 적어 돌려줍니다. 페이지 파일은 손으로 고치지 않고 이 명령으로만 읽고 씁니다(빠뜨림·꼴 어긋남을 도구가 막음).

근거: `00_공통문서/제작페이지_설계/기능명세_v001.md` 1부 2-1(파일 꼴)·3(흐름)·7(약속)·7-1(명령).

## 명령 꼴

```bash
python 10_제작페이지/에이전트.py <명령> --캐릭터 <이름> --단계 <번호> [인자]
```

- 저장소 루트에서 부른다. 결과는 JSON 한 덩어리. 잘못되면 `{"오류": ...}`와 종료 코드 1 — 이유를 읽고 고쳐 다시 부른다.
- 캐릭터 이름은 `01_캐릭터/` 아래 폴더 이름(예 `온천_검사`). 단계 번호는 1~11(페이지 윗줄의 "N단계").
- 단계를 모르면 `01_캐릭터/<이름>/제작페이지/<NN_단계>/`에서 `"묶음상태": "보냄"`인 `보내기_*.json`이 있는 단계를 찾는다.

| 명령 | 하는 일 |
| --- | --- |
| `받기` | 가장 오래된 "보냄" 묶음을 받아 요약을 출력하고 묶음을 "처리 중", 단계를 "진행 중"으로. 다른 묶음에 합쳐진 묶음은 건너뜀. 하던 "처리 중" 묶음이 있으면 그것을 다시 줌(`다시받음`). 없으면 `"결과": "없음"` |
| `사본 [--까닭 "<글>"]` | 작업본을 `<단계>/되돌리기/<시각>.blend`로 복사(옆 `.json`에 그때의 알림). 디스크가 모자라면 거부. 10개 넘으면 `지울후보`만 출력(지우지 않음 — 사용자에게 목록을 보이고 물은 뒤 지움) |
| `후보 <파일.json>` | 훑어서 찾은 후보·묻지 않고 고친 것을 검사해 `후보_<시각>.json`으로. 단계 "결정 대기" |
| `처리 <묶음> <파일.json>` | 처리 결과를 검사해 `처리_<시각>.json`으로, 묶음 "처리됨", 단계 "결정 대기". **항목이 하나라도 빠지면 쓰지 않고 거부** |
| `실패 <묶음> "<이유>"` | 끝내지 못했을 때. 묶음 "실패", 단계 "막힘", 알림에 이유. 사용자는 페이지에서 다시 보낼 수 있음 |
| `알림 "<글>" [--종류 안내\|결정 필요\|막힘]` | 결정 칸 맨 위에 보이는 알림(3줄 이하). 앞 알림은 `알림기록.json`에 쌓임 |
| `상태 <상태>` | 단계 상태 바꾸기. `끝`은 거부(사용자가 페이지에서만 누름) |
| `보기갱신` | 작업본을 바꾼 뒤. 켜져 있는 서버에 알려 새 3D 보기를 만들게 함(서버가 꺼져 있으면 직접 만듦) |
| `부위 <파일.json>` | 부위 목록 쓰기. 사용자가 바꾼 부위 이름은 이어받음. 보통은 `부위만들기.py`가 작업본에서 만들고, 이 명령은 직접 만든 목록을 넣을 때 |
| `승인요청 <파일.json>` | 유료 실행(2·4·5·6·8단계)의 승인 요청. 파일 꼴 `{"무엇": "모델 생성", "명령": "tripo generate …", "크레딧": 100 또는 "모름", "횟수": 1}`. 명령은 `tripo generate\|model\|mesh\|anim\|make`만, 파일 경로는 저장소 기준, `-o`·`--no-wait`·API 키는 넣지 않음. 페이지의 승인 상자에 그대로 보이고, **사용자가 승인을 누르면 서버가 실행**한다(에이전트는 tripo를 직접 실행하지 않음). 기다리는 앞 요청은 무효가 됨. 실행이 끝나면 알림에 받은 파일 폴더가 적힘 → 에이전트가 이어서 확인 |
| `그림판정 <파일.json>` | 1단계(`--단계 1`) 그림의 다섯 범주 자가 검수와 등신. 꼴 `{"번호": "기준001", "판정": {"요구사항 준수": {"판정": "충족", "근거": "…"}, …다섯 범주 모두}, "등신": 2.5, "등신근거": "정수리~신발 바닥 ÷ 정수리~턱", "탈락": false}`. 판정은 `충족·보완 필요·사람 확인·해당 없음`(충족이 아니면 근거 필수, 기준 그림의 "시점 간 일관성"은 `해당 없음`). 기준 그림은 등신·등신근거 필수. 판정이 있어야 사용자가 승인할 수 있다 |
| `그림등록 <파일.json>` | 가져온 그림·Codex 앱에서 만든 그림을 1단계 목록에 넣음. 꼴 `{"종류": "기준" 또는 "시트", "파일": "저장소 기준 경로", "출처": "…"}`. 시트면 서버 도구로 네 장을 자름 |
| `생성요청 [입력 파일]` | 2·4·5·6단계 승인 요청을 SSOT 기본값으로 만듦(W10). 2단계는 파일 없이(상태.json 2단계 입력 네 장, 검사 실패면 거부). 4·5·6단계는 `SSOT/도구/TRIPO입력내보내기.py`로 낸 파일의 저장소 기준 경로. 6단계 입력이 삼각형 8만을 넘으면 거부 |
| `생성확인 <파일.json>` | 받은 결과 확인을 `<단계>/확인.json`에 씀(W10). 꼴은 아래 "2·4·5·6단계에서" |
| `텍스처진행 <파일.json>` | 7단계 정리 차례 체크(W12). 꼴 `{"끝": [1,2], "글": {"2": "…"}}`. 1 여백 채우기(5-5), 2 그림 정리 공통 공정(5-6), 3 누가 봐도 흠인 것을 묻지 않고 고침 |
| `텍스처검수 <파일.json>` | 7단계 독립 검수(5-7) 한 회차(W12). 꼴은 아래 "7단계에서" |
| `리깅요청 <입력 파일>` | 8단계 오토 리깅 승인 요청(W13). 입력은 `SSOT/도구/TRIPO입력내보내기.py`로 낸 GLB의 저장소 기준 경로. 몸 유형은 리그 체크 추천값(없으면 biped) |
| `리깅확인 <파일.json>` | 8단계 받은 것 확인(6-0의 끝 표시, W13). 꼴은 아래 "8·9단계에서" |
| `리깅교차 <파일.json>` | 9단계 시험 동작마다 교차 수와 관통이 남은 장(W13) |
| `리깅비교 <파일.json>` | 9단계 후보 비교 줄(W13) |
| `동작옮김 <파일.json>` | 10단계 옮긴 결과(동작마다 성공·교차 수·관통 장·새 관통, W14). 꼴은 아래 "10·11단계에서" |
| `동작생성요청 <프리셋,…>` | 10단계 TRIPO 동작 생성 승인 요청(W14, 1~5개, 예 `walk,run`). 8단계를 TRIPO로 리깅한 작업 번호가 있어야 함. **해 본 적 없음 — 값·가격을 사용자에게 알림** |
| `내보내기결과 <파일.json>` | 11단계 Unity로 내보낸 검사표(W14). 꼴은 아래 "10·11단계에서" |

## 2·4·5·6단계(TRIPO 생성 계열)에서 (W10)

- **요청**: `생성요청`. 처음 쓰는 값(특히 4단계 리토폴로지)은 그때의 `tripo <명령> --help`로 값·가격이 같은지 먼저 본다(값의 출처는 tripo-cli 0.11.2 안내). 다르면 `승인요청`으로 고친 값을 낸다.
- **실행은 서버가 한다**: 사용자가 승인을 누르면 서버가 한 번 실행하고, 받은 파일은 `<단계>/받은것/<시각>/`, 알림 "… 실행 끝"(기본은 가짜 실행 — 받은 파일은 `가짜_받은값.json` 하나).
- **받은 뒤**: 받은 것을 작업본 방향·크기로 되돌리고(`SSOT/도구/TRIPO받은것되돌리기.py`), 작업본에 넣기 전에 `사본`, 넣은 뒤 `보기갱신`, 그다음 `생성확인`. 꼴(모든 항목이 꼭 있어야 함, `받은파일`·`메모`는 선택):
  - 2단계(2-2): `{"파일구성": "FBX 1개 …", "면수": 11065, "방향": "앞 +x(TRIPO 원본)", "텍스처해상도": "없음", "뼈수": 0, "동작": []}`
  - 4단계: `{"면수전": 20257, "면수후": 19980, "파츠수전": 4, "파츠수후": 4, "대칭점검": true, "접합부점검": true, "고친것": "…"}` — 면 수는 삼각형 수
  - 5단계(5-3): `{"받은그림": ["…/파츠_몸.png", …], "정점자리같음": true, "형태": "같음", "UV": "새로 펴짐", "객체구성": "4개 그대로"}` — 정점 자리가 다르면 `false`로 쓰고 `알림 --종류 막힘`
  - 6단계(4_UV 수치): `{"겹침": 0, "최소간격": 8, "UV범위안": true, "뒤집힌삼각형": 0, "그림비교통과": true, "격자직접봄": true, "가다듬음": false}` — 가다듬었으면 `"다시구움": true`(5-4)
- 페이지의 "이 단계 끝"이 이 확인과 2부의 끝나는 조건을 본다. 모자라면 사용자에게 무엇이 모자란지 보인다.

## 3단계(메시 정리)에서 (W11)

두 번만 멈춘다(기능명세 2부 15절). 순서는 SSOT `단계/3_메시`의 1~10. 그 사이에는 묻지 않고 한다.

1. 순서 1~5(살펴보기, 노이즈 조각 후보 **표시만**, 파츠 나누기, 대칭으로 만들 것 정하기, 대칭 중심 재기)를 하고 `메시진행 <파일>` — `{"끝": [1,2,3,4,5], "글": {"2": "조각 33개 중 노이즈 후보 2"}}`. 계획을 정하기 전에는 6~10을 적지 못한다.
2. **멈춤 1**: `SSOT/도구/메시검사.py`를 돌리고(검사결과.json에 조각·후보마다 `면번호`가 있어야 함 — 옛 결과면 다시 돌림), 칸 그림을 직접 보고 1차로 거른 번호만 `메시멈춤 <파일>`:
   `{"멈춤": "계획 확인", "검사결과": "<저장소 기준 경로>/검사결과.json", "고른번호": ["상체 조각1"], "후보": [], "계획": {"파츠": [{"이름": "파츠_상체", "면": 1537}], "대칭": [{"파츠": "파츠_상체", "대칭": true, "기준쪽": "+x", "이유": "…", "그림": ["<좌우 절반 나란히 그림>"]}, {"파츠": "파츠_헤어", "대칭": false, "이유": "앞머리 비대칭"}]}}`
   — 고른 번호는 후보 A, B…(파츠·면 번호·근거 그림)로 바뀐다. 기준쪽은 화면 오른쪽 = `+x`. 대칭으로 만들 파츠는 좌우 절반 그림이 꼭 있어야 한다. 알림 "결정 필요"는 명령이 쓴다.
3. 사용자가 판단과 대칭 답을 보내고 "보냈어" → `받기`의 `멈춤답.대칭`(파츠마다 `대칭`·`기준쪽`)이 **정한 계획**이다(`03_메시정리/계획확정.json`에도 있음). 지울 후보(고칠 것)는 지우기 전에 입력 그림의 그 자리를 확대해 본다(입력 그림에 있으면 "안 고침: 입력 그림에 있음"). `처리`로 마친다. 정한 대칭 기준은 뒤에서 바꾸지 않는다.
4. 순서 6~10(정한 기준 쪽대로 대칭, 가운데 맞추기, 접합부 검사·흠 후보, 음영 손보기)을 하고 `메시진행 {"끝": [6,7,8,9,10]}`. 노멀만 이상한 곳은 묻지 않고 고치고 "고친것"으로.
5. **멈춤 2**: `메시멈춤` — `{"멈춤": "결과 확인", "검사결과": "…", "고른번호": [...남은 흠], "고친것": [표시 항목(근거그림에 전후)], "결과": {"접합부판정": [{"접합부": "목", "판정": "통과|보완 필요|사람 확인", "근거": "…"}], "다각도그림": ["…"]}}`. 사용자는 판단해 보내거나 "이 단계 끝"을 누른다.
- 끝나는 조건(페이지가 봄): 순서 1~10, 계획 정함, 마지막 멈춤 2의 후보를 모두 판단해 보냄, 접합부 판정이 모두 "통과", 여러 방향 그림, 처리 안 된 묶음 없음. 고친 뒤 접합부가 통과가 되면 멈춤 2를 다시 낸다.
- 사용자가 멈춤 2에서 한 답이 멈춤 1의 결정을 뒤집게 되면(구조가 잘못됨) 그 결정을 "앞에서 물을 결정"으로 옮기자고 보고한다(1부 3-1b).

## 7단계(텍스처 수정)에서 (W12)

순서는 SSOT `단계/5_텍스처` 5-5~5-7(기능명세 2부 19절). 그 사이에는 묻지 않고 한다.

1. 5-5 여백 채우기, 5-6 그림 정리 공통 공정을 돌리고 `텍스처진행 {"끝": [1, 2]}`.
2. (자동 검사기 후보: 기능명세 28절대로 검사기 시험 결과를 본 뒤에 붙인다. 지금은 쓰지 않는다.)
3. 누가 봐도 흠인 것(끊김·꺾임·얼룩)은 묻지 않고 고치고(메모리 "텍스처 흠은 묻지 않고 고치기"), `후보`에 "고친것"(근거그림에 전후)으로 → `텍스처진행 {"끝": [3]}`. 취향은 후보로만.
4. **독립 검수(5-7)**: Codex Astra에게 맡긴다(작성자 견해 없이). 받은 뒤 `텍스처검수 <파일>` —
   `{"상태": "받음", "검수자": "Codex Astra", "보고": "<저장소 기준 경로>", "넓은그림": ["<넓게 본 그림>"], "지적": [{"종류": "선이 끊김·꺾임", "자리": {"파츠": ["파츠_상체"], "면": {"파츠_상체": [12, 13]}}, "메모": "칼라 줄 계단", "근거그림": ["…"]}]}`.
   지적은 후보(누가 "독립 검수", 번호는 비우면 다음 글자)로 같은 목록에 들어간다. 판단하지 않은 앞 후보·고친 것은 새 후보 파일에 이어 담긴다. 받지 못하면 `{"상태": "받지 않음", "이유": "Codex 사용량 한도"}`(사용자도 페이지 옆 기둥에서 적을 수 있다).
5. 확대 지적이 끝없이 이어지면 더 쫓지 않고 넓게 본 그림을 `넓은그림`에 넣어 보인다. 멈출 곳은 사용자가 정한다(방침 "완벽을 목표로 하지 않음").

## 1단계(그림 생성)에서 (W09)

- **새 캐릭터 입력**: 사용자가 페이지에서 입력을 보내면 `01_캐릭터/<이름>/제작페이지/01_그림생성/입력_<시각>.json`이 생긴다. "보냈어"를 들으면 이 파일을 읽어 `SSOT/13_새캐릭터_입력항목.md` "받은 뒤"대로 캐릭터 노트(`SSOT/캐릭터/<이름>.md`, 설정 표의 상태 칸 + 한국어·영어 조립값)를 만든다. 페이지는 노트의 "설정" 표를 띄우고, 사용자가 처음 "생성"을 누를 때 설정 표를 확인받는다.
- **생성은 서버가 한다**: 사용자가 "생성"을 누르면 서버가 요청문을 조립하고(`요청문_조립.py`), 영어본을 Codex에 넘겨 그린다(기본은 가짜 실행). 시트는 서버가 곧바로 네 장으로 자른다. 결과는 `01_캐릭터/<이름>/02_설정화/페이지생성_<시각>_<종류>/`(요청문 사본·생성기록.json 포함).
- **생성이 끝나면**(알림 "… 생성 끝"): 그림을 열어 SSOT `단계/1_이미지` "그림 검수"대로 보고 `그림판정`을 쓴다. 등신을 재고 근거를 적는다. 손 구조가 기준 밖이면 "구조의 타당성: 보완 필요"(사용자가 승인하려 하면 페이지가 한 번 더 묻는다). 기형이면 `"탈락": true`.
- **"보냈어"(1단계 표시)**: 표시의 `자리.그림`이 `{파일, 범위 [[x1,y1],[x2,y2]](그림 화소), 획, 붓}`이다. 수정 요청문을 만들어 고칠 그림을 새로 받는 것은 사용자에게 묻고 한다(Codex 한도를 씀).
- 승인·탈락 판단은 사용자가 한다. 시트 승인 때 서버가 네 장을 `03_TRIPO/실험_NNN_입력이미지/후보_A/`에 두고 `TRIPO입력_검사.py`를 돌린다(통과하면 2단계 입력이 됨).

## "보냈어"를 들으면 (차례)

1. `받기` → 출력의 `표시`(사용자가 칠한 것: 번호·종류·파츠·부위·면 수·메모·반대쪽도·옛버전)와 `후보판단`을 읽는다. 자리의 면 번호 전체는 출력의 `경로`(보내기 파일)에 있다.
2. 작업본을 바꾸기 **전에** `사본`. 출력의 `파일`을 적어 둔다.
3. 고친다(Blender는 `SSOT/도구/블렌더실행.sh`). 원칙은 `AGENTS.md`와 SSOT: 고친 곳은 여러 방향에서 열어 본다, 형태를 바꾸는 일은 묻는다 등.
   - 표시의 `옛버전`이 참이면 칠한 뒤 작업본이 바뀐 것이다. 자리를 다시 찾고, 못 찾으면 "안 고침: 자리를 못 찾음".
   - 후보 판단이 `둘 것`이면 고치지 않고 "안 고침: 사용자가 둘 것으로 판단", `모름`이면 고치지 말고 이유에 무엇을 보고 판단할지 적는다.
4. 처리 결과 파일을 쓴다(아무 곳, 예: 스크래치). **묶음의 모든 번호마다 한 줄**:

   ```json
   {
     "결과": [
       {"번호": "①", "처리": "고침", "근거그림": ["01_캐릭터/<이름>/.../전후_①.png"], "이유": ""},
       {"번호": "②", "처리": "안 고침", "이유": "입력 그림에 있는 주름이라 둠"},
       {"번호": "A", "처리": "안 고침", "이유": "사용자가 둘 것으로 판단"}
     ],
     "되돌리기사본": "01_캐릭터/<이름>/제작페이지/<NN_단계>/되돌리기/<시각>.blend",
     "열어본그림": ["...png"],
     "만들기만한그림": []
   }
   ```

   - `고침`이면 `근거그림`(전후 그림, 저장소 안 경로)이 꼭 있어야 한다. `안 고침`이면 `이유`가 꼭 있어야 한다.
   - 고친 것이 하나라도 있으면 `되돌리기사본`(2번의 경로)이 꼭 있어야 한다.
   - 그림 경로는 저장소 루트 기준이고 실제로 있어야 한다.
5. `처리 <받기가 준 묶음 이름> <처리 결과 파일>`. 거부되면 이유대로 고쳐 다시.
6. `알림 "<무엇을 고쳤고 무엇을 안 고쳤는지 한두 줄. 열어 본 그림 N장 / 만들기만 한 그림 N장>"`. 사용자의 결정이 필요하면 `--종류 "결정 필요"`.
7. 작업본을 바꿨으면 `보기갱신`.
8. Claude 앱에서 사용자에게 짧게 보고한다: 페이지에서 전후를 보고 또 보내기 / "이 단계 끝" / "되돌리기"를 고르면 된다고.

끝내지 못하면 아무 때나 `실패 <묶음> "<이유>"`.

- "이 단계 끝"은 사용자만 누른다. 에이전트는 `상태`로 끝을 쓸 수 없다.
- 되돌리기 사본은 지우기 전에 사용자에게 목록을 보이고 묻는다.
- 페이지를 쓰는 동안 서버(`http://127.0.0.1:8765/`)를 끄지 않는다. 화면은 몇 초 안에 이 명령이 쓴 파일을 읽어 바뀐다.
