## 상태.json

꼴은 기능명세 2-1(`꼴버전` 1, 한국 시각, `단계`는 번호 1~11 목록)을 따른다. `01_캐릭터/<이름>/제작페이지/상태.json`.

- 서버가 2-1 밖에 더 쓰는 항목: 맨 위 `작업본`(저장소 기준 작업본 경로, 없으면 빈 글. `작업본해시`를 계산할 파일).
- `단계[].상태`가 `준비됨`/`입력 없음`이면 서버가 `입력`의 파일이 모두 있는지로 다시 정한다(1부 4-2). 모르는 값·깨진 단계는 그 단계만 `알 수 없음`과 이유.
- `입력`·`작업본`은 저장소 안의 일반 파일만 인정한다(`..`, 절대 경로, 네트워크 경로, 폴더, 바깥을 가리키는 연결점은 "없는 입력").
- `표시`(`앞 단계 안 거침`, `앞 단계가 바뀜`)는 파일에 적힌 것을 보인다. 서버의 `앱.단계상태쓰기()`로 쓰면 저절로 적힌다: 앞 단계가 끝이 아닌데 시작하면 `앞 단계 안 거침`, 끝인 단계를 다시 고치기 시작하면 뒤의 끝인 단계마다 `앞 단계가 바뀜`. `캐릭터 노트 없음`은 파일에 적지 않고 서버가 계산한다.
- 쓰기는 파일마다 잠그고, 고유한 임시 파일에 쓴 뒤 바꿔 넣는다. 모르는 항목은 지우지 않는다.

## 3D 보기용 GLB (W01)

- 서버: `GET /api/모델?이름=<캐릭터>` → `상태`가 `작업본 없음` / `만드는 중`(뒤에서 만듦, `경과초`) / `됨`(`주소`) / `실패`(`오류`, `로그`). 화면은 `만드는 중`이면 다시 묻는다. `마지막`은 검사를 통과한 가장 최근 GLB(작업본이 바뀌는 중에 대신 보일 것). `&다시=1`이면 캐시를 무시. 같은 해시로 실패했으면 `다시=1` 전까지 다시 돌리지 않는다.
- 파일: `01_캐릭터/<이름>/제작페이지/보기/<작업본해시>.glb`, `.json`(파츠·면 수·뼈대·동작·찾지 못한 텍스처·검사 통과), `_로그.txt`(Blender 출력). `보기/.gitignore`가 모두 git에서 뺀다. `GET /보기/<이름>/<해시>.glb`로만 내준다.
- 내보내는 것: 렌더에서 숨기지 않은 메시 객체(예: `보관`의 `TRIPO_원본`은 빠짐)와 그 뼈대·동작 전부, 첫 번째 UV 층(TEXCOORD_0), 텍스처(GLB 안). 수정자는 적용하지 않음(아마추어는 스킨).
- 면 번호: 정점 속성 `_FACEID`(실수로 저장, 정수 값). three.js에서는 `geometry.attributes._faceid`. 삼각형 세 정점의 값이 늘 같다(검사가 확인).
- Blender는 Git Bash로 `SSOT/도구/블렌더실행.sh`를 부른다. bash는 `C:\Program Files\Git\bin\bash.exe` 등에서 찾고(WSL의 bash는 쓰지 않음), 다르면 환경변수 `가마우지_BASH`.

## 3D 보기 (W02)

- `정적/보기3d.js`(모듈). 3~11단계의 가운데 칸 위에 보기 줄과 도구 줄을 붙인다. 화면을 다시 그려도 같은 WebGL 보기를 다시 붙인다(`보기3d.붙이기`).
- 조작: 왼쪽 끌기 옮기기(가운데 버튼·Shift+왼쪽도), 오른쪽 끌기 돌리기(각도 제한 없음), 휠 확대(마우스 자리 기준), 두 번 누르기 회전 중심+다가감, Alt+클릭 이 파츠만. 단축키 1~4 방향, 5 원근/평행, F 처음 자리, H 파츠 목록, Space(누르는 동안) 전.
- 방향: 앞 = glTF +z(Blender -Y), 옆 = +x 쪽, 아래 = 앞 아래 25도(SSOT 40 4절).
- 전후 비교의 "전": 서버 `/api/모델`의 `전`(지금 해시가 아닌, 검사를 통과한 가장 최근 GLB).
- 그림 상수(시야각·감도·색)는 `보기3d.js` 맨 위 한 곳. 색은 디자인 토큰에서 읽는다.
- 시험용: `보기3d.재기(ms)` → 초당 화면 수, 한 장 그리는 시간, 빈 화면 수.

## 칠하기와 표시 (W03)

- `정적/칠하기.js`(모듈). 칠하는 단계(3·6·7·9·10, 처리 목록은 서버 `처리목록`)에서 도구 줄 맨 앞 보기·붓·지우개(V·B·E)와 가운데 칸의 표시 목록을 쓴다. Shift+휠 붓 크기, Ctrl+Z/Ctrl+Y 취소·다시(50번).
- 면 고르기: 보이는 메시를 면 번호 색(R·G·B = 면 번호+1, A = 파츠 번호+1)으로 따로 그린 그림에서 붓 원 안 화소를 읽는다. 화면에 보이는 면만 칠해진다.
- 서버: `GET /api/표시?이름=&단계=`(작성 중·취소 기록·보낸 묶음과 처리 결과·가장 최근 후보), `POST /api/작성중`(자동 저장, 주인 탭만), `POST /api/보내기`(앞 묶음이 "보냄"이면 `합치기` 참/거짓을 꼭 받음). 맥박(`/api/탭`)에 `단계`를 주면 `바뀜.표시`(후보·보내기·처리 파일이 바뀌었는지).
- 파일(단계 폴더 `제작페이지/<NN_단계>/`): `작성중.json`(2-1 + `다음번호`·`묶음번호`), `작성중_기록.json`(취소 기록, 페이지만 씀), `보내기_<시각>.json`. 표시 항목에 `작업본해시`·`카메라`를 더 적는다. 후보 판단은 `{후보파일, 번호, 판단}`.
- 시험용: `칠하기.시험_면(x, y, r)`(캔버스 좌표의 원 안 면들), `칠하기.시험_고르기()`.

## UV 그림 나란히 (W04)

- `정적/uv그림.js`(모듈). 6·7단계(`상수.단계`)에서 3D 보기 오른쪽에 UV 그림 칸, 도구 줄 끝에 "UV 고정·UV 텍스처·UV 맞춤". 6단계는 처음에 UV 선만, 7단계는 텍스처를 깐다. 텍스처는 GLB 안의 그림을 그대로 쓴다(서버에 따로 묻지 않음).
- 모델 위 마우스 → 맞힌 면의 UV에 파란 십자(파츠도 따라 바뀜, "UV 고정"·"이 파츠만"이면 멈춤). UV 위 마우스 → 그 UV 자리를 쓰는 면마다 모델 위에 파란 점(겹친 UV면 여럿).
- UV 위 칠하기: 붓·지우개는 3D와 같다(B·E·V, Shift+휠 크기). 붓 원에 닿은 UV 삼각형의 면이 표시에 들어간다. 한 번 누르면 그 자리를 덮는 면만. 숨긴 파츠는 칠할 수 없다. UV 칸에서 휠 확대, 오른쪽·가운데(붓을 안 들었으면 왼쪽도) 끌기 옮기기, 두 번 누르기 맞춤.
- 칠한 곳은 3D와 같은 색으로 UV에도 보인다(`칠하기.js`의 `겹침모음`과 `칠하기겹침` 사건).
- 표시에 더 적는 것(6·7단계): `자리.UV`(2-1: 파츠 → `[[x1,y1],[x2,y2]]` 화소 범위, 왼쪽 위가 0,0인 그림 화소 = glTF UV × 그림 크기. Blender UV의 v와 위아래 반대), `자리.UV조각`(그 표시가 UV 조각 둘 이상에 걸치면 조각마다 범위 — 이음매를 지나는 표시). 목록 설명에 "UV 조각 N개(이음매를 지남)".
- UV가 한 점에 모인(넓이 0) 삼각형은 UV 칸에서 고르지 않는다.
- 시험용: `uv그림.시험_모델에서(x, y)`, `uv그림.시험_UV에서(u, v)`, `uv그림.시험_화면자리(u, v)`, `uv그림.시험_파츠(이름)`.

## 부위 (W05)

- 만들기(에이전트): `python 10_제작페이지/부위만들기.py --폴더 <저장소 루트> --캐릭터 <이름>` → `01_캐릭터/<이름>/제작페이지/부위.json`(2-1 꼴 + `번호`·`자동이름`·`중심`·`근거`). Blender 출력은 `보기/부위_로그.txt`. 작업본은 읽기만(전후 해시 비교).
- 묶는 법(`블렌더/부위만들기.py`): 파츠마다 이어진 덩어리 → 큰 덩어리(파츠 면 30%·200면 이상)는 UV 조각으로 나누고 작은 조각(3% 미만)은 이웃에 붙임(덩어리당 6개까지). 이름은 [좌우] + [뼈 가중치의 몸 낱말 또는 파츠 상자 안의 자리]. 좌우는 보는 사람 기준(오른쪽 = +x). 같은 이름끼리는 위/아래·앞/뒤를 붙이고 그래도 겹치면 2, 3.
- 이어받기: 옛 목록의 `사용자가바꾼이름` 부위를 같은 파츠에서 면이 절반 넘게 겹치거나, 중심이 파츠 크기의 10% 안이고 면 수 0.5~2배인 새 부위에 옮긴다.
- 화면(`정적/부위.js`): 도구 줄 "파츠 숨김"과 "형태만" 사이 "부위 ▾". 부위 누르기 → 그 부위만 밝게(나머지 흐리게/숨김), 카메라 맞춤, UV 칸도 그 조각만 밝게. 줄마다 보이기(부위 숨김)·"이름". "이 부위 안에서만 칠하기". 칠한 표시의 `자리.부위`를 부위 이름("상체 › 왼쪽 소매")으로 적는다. 숨긴 부위는 칠할 수 없다.
- 그리는 법: GLB는 면마다 정점이 따로라 정점 값 `bu_flag`(0 보통·1 흐림·2 숨김)를 넣고 재질 셰이더에서 읽는다(`보기3d모양` 사건 때 새 재질에도 입힘). 칠하기의 고르기 그림도 2를 뺀다.
- 서버: `GET /api/부위?이름=`, `POST /api/부위이름 {이름, 탭, 번호, 새이름, 작업본해시}`(빈 이름 = 자동 이름으로 되돌림, 같은 파츠에 같은 이름 거부). 맥박의 `바뀜.부위`(부위.json 수정 시각)로 다시 읽는다. 작업본해시가 지금 모델과 다르면 회색 "부위 목록이 옛 것".

## 결정 칸과 에이전트 명령 (W06)

- 오른쪽 칸(`정적/결정.js`): 에이전트 알림(종류별 색, 작업본이 바뀌면 "옛 알림"), 결정 단추 세 개(3·7·9단계: 이 단계 끝 / 고쳐 줘 / 되돌리기. 다른 단계의 승인·다시 생성·옮기기·내보내기는 W07·W09·W14가 채움 — 지금은 막아 둠), 되돌리기 목록 상자, 실패한 묶음 "다시 보내기".
- 서버: `GET /api/결정`, `POST /api/결정`(이 단계 끝 / 그래도 끝 / 고쳐 줘), `POST /api/되돌리기`, `POST /api/다시보내기`, 맥박의 `바뀜.결정`(알림·보내기·처리·되돌리기 파일).

## 승인과 TRIPO 실행 (W07)

- `승인.py`(서버가 불러 씀). 유료 단계 2·4·5·6·8의 결정 칸에 승인 상자(`정적/결정.js`): 무엇, 크레딧(모르면 굵게 "크레딧 모름"), 횟수, 지금 잔액, 명령 그대로(고정폭, 줄 바꿈), 실행 뒤에는 작업 번호·쓴 크레딧·잔액 전후·받은 파일·실제로 쓴 값.
- 요청: 에이전트가 `에이전트.py 승인요청 <파일.json> --단계 N`({무엇, 명령, 크레딧, 횟수})으로 `승인_<시각>.json`(승인 "대기", 실행 "안 함", 값해시 = 명령의 SHA-256)을 쓴다. 같은 단계에 기다리는 요청이 있으면 그것은 "거절"(새 요청으로 바뀜, 무효). 단계 화면(W09~W14)은 같은 함수 `승인.요청만들기`를 쓴다.
- 명령은 `tripo generate|model|mesh|anim|make …`만 받는다. `-o/--out`, `--no-wait`, `--yes`, API 키처럼 보이는 글은 거부. 저장소 기준 파일 경로는 실행할 때 실제 경로로 바꾸고 `--json`을 붙인다(그 값을 `결과.실제값`에 적음).
- 승인(`POST /api/승인`): 페이지가 보인 명령·크레딧·횟수·값해시를 보낸다. 서버는 가장 최근 요청이고, 대기·안 함이고, 파일의 값해시가 명령과 맞고, 보인 값이 파일 값과 같고, 잔액이 모자라지 않을 때만 "실행 중"으로 바꾸고 **한 번** 실행한다(한 번에 하나). 실행 중 단계 "진행 중", 끝나면 "결정 대기"(실패면 "막힘")와 알림. 서버가 실행 중에 꺼진 요청은 다시 실행하지 않고 "실패"로.
- 다시 생성(`POST /api/다시생성`): 가장 최근 요청과 같은 값의 새 대기 요청. 실행하지 않는다.
- 받은 파일: `<단계 폴더>/받은것/<시각>/`(실행 폴더), 로그 `tripo_로그.txt`. 화면·파일·로그에 적는 글은 모두 API 키를 지우고 쓴다(`승인.가리기`).
- **실행 모드**: 기본은 **가짜 실행**(TRIPO에 요청하지 않음, 크레딧 0, 잔액은 `로컬/TRIPO잔액_가짜.json`, 처음 1000). 진짜는 `제작페이지.py --진짜실행`일 때만 — `node <tripo-cli의 cli.js>`를 셸 없이 부르고(환경 변수 `가마우지_TRIPO`나 `로컬/tripo-cli/` 설치본, 없으면 보존해 둔 tgz를 거기 설치), 실행 전후 `tripo balance`로 잔액을 `로컬/TRIPO잔액.json`에 기록. **진짜 실행은 시험하지 않았다.** 시험용 `--가짜결과 성공|실패|잔액부족`.

- 넣기(`POST /api/가져오기/넣기`): 원본을 `01_캐릭터/<이름>/03_TRIPO/가져온것_<시각>/`에 그대로 복사(해시 확인), 네 방향 그림(`보기_*.png`), 기록 `가져오기.json`. 앞이 -y(작업본 방향)가 아니면 z축으로 돌린 `되돌림_<이름>.blend`를 만들어 입력으로(GLB·FBX는 `SSOT/도구/TRIPO받은것되돌리기.py`에 크기 1·높이맞춤 끔, OBJ·blend는 `가져오기검사.py --돌리기`). `상태.json`의 그 단계 입력·출처(`TRIPO 웹(작업 …), 웹에서 가져옴, 생성 설정 모름` 등)·상태 "준비됨"(2단계 + TRIPO 웹이면 "끝").
