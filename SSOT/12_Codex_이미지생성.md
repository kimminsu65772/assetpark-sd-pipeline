# Codex로 그림 만들기

## 한눈에 보기

- **기록이 남은 교복 사무라이의 그림(기준 그림 v001~v003, 멀티뷰, 손 수정본)은 모두 Codex의 내장 이미지 도구로 만들었다.** 컨셉 초안을 만든 기록은 찾지 못했다. 당시에는 Codex 앱의 채팅에서 만들었다. 에이전트가 명령줄로 맡기는 방식도 2026-11-23에 한 장으로 시험해 되는 것을 확인했다(아래 "명령줄 시험").
- **Codex에 넘기는 것은 그림 생성에 필요한 것뿐이다**: 조립한 요청문과 참고 그림. 사용자의 이름·이메일·프로젝트 사정은 넣지 않는다.
- **Codex는 사용량 한도로 자주 멈춘다.** 멈추면 어디까지 됐는지 그대로 보고하고, 한도가 풀리는 시각을 적는다.
- **생성이 끝난 것과 검수를 통과한 것은 다르다.** 받은 그림은 [[40_검수와_보고]]로 검수한다.

## 명령줄 시험

2026-11-23에 한 장으로 시험했다(사용자 승인). **명령줄로 맡겨도 그림이 만들어지고, 참고 그림도 넘어간다.** 내용은 교복 사무라이의 기준 그림 재현이고, 자료는 모두 `01_캐릭터/교복_사무라이/02_설정화/Codex명령줄_시험_2026-11-23/`에 있다.

### 명령

그림을 받을 폴더로 들어가서 실행한다(Git Bash). Codex가 파일을 쓸 수 있는 범위가 그 폴더로 한정된다.

```bash
codex exec -m gpt-6.2-astra --sandbox workspace-write -i <참고 그림.png> -o 보고_Codex.md - < Codex_지시문.txt
```

- `Codex_지시문.txt` = 지시 다섯 줄 + 조립한 요청문 전체. 지시의 내용: 내장 이미지 도구를 한 번만 호출, 첨부 그림을 참고 그림으로 넘김, 요청문을 고치지 않고 그대로 prompt로 씀, 재시도·수정 금지, 결과 PNG를 현재 폴더에 바이트 그대로 복사, 도구에 넘긴 인자·시각·경로·크기·해시를 보고, 폴더 밖 파일을 건드리지 않음. 본은 시험 폴더의 `Codex_지시문.txt`.
- 참고 그림은 `-i`로 첨부하고, 같은 그림을 작업 폴더에도 둔다. Codex는 그 파일의 절대 경로를 도구의 `referenced_image_paths`에 넣었다.
- `-i` 바로 뒤에 `-`(표준 입력)를 두지 않는다(`-i`가 파일을 여러 개 받는다). 사이에 `-o`를 둔다.

### 확인한 것

| 항목 | 결과 | 어떻게 확인했나 |
| --- | --- | --- |
| 그림이 만들어지나 | 됨. 도구 `image_gen__imagegen`을 1회 호출 | Codex의 보고와 실행 로그 |
| 저장되는 곳 | `C:\Users\<사용자>\.codex\generated_images\<세션 ID>\exec-<ID>.png`. 세션 ID는 실행 로그 머리의 `session id` | 폴더에 새 세션 폴더가 생긴 것을 직접 확인 |
| 형식과 크기 | PNG, 1218×1292, 약 1.5 MB. 참고 그림과 같은 크기였다(참고 그림의 크기를 따르는지는 한 번으로는 알 수 없다) | 파일을 직접 열어 잼 |
| 작업 폴더로 복사 | 지시대로 복사됨. 원본과 복사본의 SHA256이 같다고 보고 | 복사본의 해시는 직접 계산해 보고와 같음을 확인. 원본의 해시는 Codex의 보고 |
| 참고 그림 | `referenced_image_paths`에 파일 경로로 넘어감 | Codex가 보고한 인자. 결과 그림이 컨셉 초안의 얼굴·헤어·배색을 따른 것을 직접 봄 |
| 요청문 | 조립한 요청문 전체가 고쳐지지 않고 `prompt`로 들어감 | 보고된 인자를 눈으로 대조(글자 단위 비교는 하지 않음) |
| 걸린 시간 | 명령 전체 2분 3초, 그 가운데 도구 호출은 약 26초 | `time`과 Codex가 보고한 시각 |
| 한도 | 한도 안내 문구 없음. 실행 로그의 `tokens used`는 40,613. 남은 한도가 얼마인지는 명령줄 출력에 나오지 않아 알 수 없다 | 실행 로그 |
| 알 수 없는 것 | 이미지 모델 이름, 품질 설정, 비용 | 도구가 알려 주지 않음 |
