# 아직 정해지지 않은 것, 초안인 것, 어긋나는 값

## 한눈에 보기

- **이 볼트의 값 대부분은 교복 사무라이 한 개에서 나온 초안이다.** 2절에 무엇이 그런지 적었다. 다른 캐릭터 1~2개에서 반복한 뒤 확정한다.
- **문서끼리 다르게 적힌 값이 있다**(1절). 임의로 고르지 않았다. 사용자가 정하면 해당 노트에 반영하고 이 목록에서 지운다.
- 두 번째 캐릭터를 시작하기 전에 꼭 정해야 하는 것은 남아 있지 않다. 나머지는 해당 단계에 가서 정해도 된다.
- 번호(A4~A14)는 다른 노트에서 가리키므로 정해진 것을 빼도 다시 매기지 않는다.

## 3. 아직 정해지지 않은 것

**그림**
- 얼굴과 눈을 그리는 방식의 글 기준(지금은 참고 그림으로만 전달).
- 선·색 규칙의 글 기준.
- 이미지 검수를 어떻게 구현할지, 자동 수정 횟수와 통과 기준("최대 2회 수정"은 제안일 뿐 확정이 아니다).
- 상세 체형을 재는 기준점, 등신 말고 다른 항목의 허용 오차.
- 스타일 참고 그림으로 교복 사무라이의 A포즈 v003을 계속 쓸지(이 그림은 비율과 컨셉을 수용한 것이고 모든 검수에서 최종 승인된 것은 아니다. 손 기준이 요청문에 들어가기 전의 그림이다).

**3D**
- 최종 내보내기 규격. 예산(삼각형 약 2만, 뼈 150개 이하, 파츠마다 1024 그림·재질 4개)은 정했고([[20_3D규격]] 1절). 기기 실측은 하지 않는다(사용자 결정, 2026-11-24).
- TRIPO Smart Mesh의 면 제한 값(교복 사무라이는 5,000으로 설정했으나 실제 면은 11,065).
- TRIPO의 3D 생성(Smart Mesh)과 오토리깅을 에이전트가 명령줄로 하는 방법과 값. 교복 사무라이는 사용자가 화면에서 했고 세부 설정이 기록에 없다.
- 새 캐릭터를 처음부터 x = 0에 두고 좌우 대칭 뼈대로 만들지.
- 표정을 텍스처로 바꾸는 구체적인 방법(갈아 끼울 그림의 수와 규격).
- 노멀을 다시 계산할지(교복 사무라이의 D13).
- 그림 한 장에 네 파츠를 모으는 방식, 좌우가 자리를 함께 쓰는 UV.
- 포니테일과 치마의 흔들림을 Unity 쪽 기능으로 넣을지.

**Unity**
- 그늘을 넣는 셰이더, 치마 재질 양면 그리기(방침은 정해졌고 아직 하지 않음).
- 동작 사이의 전환을 다루는 Animator와 이동 코드. 전환 구간에서 구운 치마가 어긋나는지.
- 속바지의 모양과 색, 메시로 만드는 법(교복 사무라이는 지운 골반 윗부분을 되살릴지와 함께. 메시 조사 D14).
- 회피 동작(구르기는 쓰지 않기로 했다. 필요해지면 다른 동작을 찾는다).
- 뼈 147개와 한 정점당 뼈 4개 제한의 영향.

**파이프라인 자동화**(사용자 방향, 2026-11-23. 기획 전이라 만들지 않음)
- 문서를 읽고 단계마다 판단하는 대신, 정해진 순서로 빠르게 도는 하나의 자동화 프로그램으로 만든다. 사람의 결정(승인·수정)과 돈이 드는 실행(TRIPO)에서만 멈춘다.
- UI로 제어한다. 방식은 **웹 화면**(이 PC에서 프로그램을 켜면 브라우저에 뜸), **이 PC에서만** 연다. Unity 안일 필요는 없다.
- 안쪽 동작(단계 실행·검사·기록)은 UI와 분리된 파이썬 코드로 두어 에이전트도 명령줄로 같은 단계를 돌린다(에이전트 제안).
- **단계마다 별도 세션에서 돈다**(사용자 결정, 2026-11-23). 한 세션이 모든 단계를 이어 하지 않고, 단계별 세션이 필요한 문서와 파일만 읽어 사용자의 토큰을 아낀다. 단계 사이의 전달은 캐릭터 노트와 정해진 폴더의 파일로 한다.
- **한 화면에서 단계별로 처리한다**(사용자 방향, 2026-11-24). 화면은 하나지만 한 번에 한 단계만 다루고, 그 단계에 필요한 정보만 띄운다: 이미지 생성 요청 → 모델 생성 → 메시 정리 → 리토폴로지 → 텍스처 생성 → Smart UV → 텍스처 수정 → 오토 리깅 → 리깅 수정 → 애니메이션 선택 또는 TRIPO 애니메이션 생성 → 내보내기(Unity 프로젝트에 바로). 리토폴로지, TRIPO 애니메이션 생성, Unity 프로젝트로 바로 내보내기는 아직 해 본 적 없다. 리토폴로지는 TRIPO에 API로 요청하는 단계다(사용자, 2026-11-24). 다른 TRIPO 유료 실행처럼 값과 크레딧을 보이고 승인받는다.
- **어느 단계에서든 시작할 수 있다**(사용자, 2026-11-24). TRIPO는 API만 쓰지 않고 사용자가 웹에서 받아 올 수도 있다. 그래서 단계마다 "파일 가져오기"가 있고, 앞 단계를 거치지 않았어도 그 단계의 입력 파일이 있으면 시작한다. 가져온 파일은 먼저 검사한다(형식, 방향·크기, UV·뼈대 유무). 웹에서 받은 것은 생성 설정을 모르므로 "웹에서 가져옴, 설정 모름"으로 기록한다.
- 검수가 필요한 단계에서는 같은 화면에서 텍스처를 입힌 3D 모델과 UV 그림을 함께 보고, 사람이 이상한 곳을 모델 위에 직접 칠해 표시한다. 표시는 면·UV 위치로 파일에 저장되어 에이전트가 읽고 고친다. 에이전트가 찾은 후보만 보는 방식으로는 사람이 찾는 흠을 놓친다(사용자, 2026-11-24). 주소는 `127.0.0.1`만, 페이지가 바깥 주소에 요청하지 않는다. Claude와의 대화는 괜찮다. PC에서만 쓴다.
- UI 제작은 따로 기획한 뒤에 한다. 지금 있는 부품: `SSOT/도구/요청문_조립.py`, `시트_자르기.py`, `TRIPO입력_검사.py`.
