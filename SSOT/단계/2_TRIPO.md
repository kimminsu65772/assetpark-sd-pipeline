# 2. TRIPO (3D 초안과 TRIPO 값)

## 한눈에 보기

- **TRIPO로 메시만 만든다(P2.0, 쿼드, 면 제한 5,000, 텍스처 끔).** 텍스처는 UV를 만든 뒤 [[5_텍스처]]에서 받는다.
- **유료 실행은 값 전체와 횟수를 보여 주고 승인받은 뒤에만 한다.** 받은 뒤에는 서버가 실제로 쓴 값을 확인한다.
- 이 노트의 "TRIPO 값"은 메시·UV·텍스처 단계가 함께 쓴다.

경로의 `B/`와 `…/SmartMesh_리깅보정/`은 `01_캐릭터/교복_사무라이/04_Blender/SmartMesh_리깅보정/`을 줄여 쓴 것이다. 실행 꼴과 버전 관리는 [[30_단계와_합격기준]].

- 실행할 때마다 값 전체와 횟수를 사용자에게 보여 주고 승인받는다. 받은 뒤에는 서버가 실제로 쓴 값을 확인한다([[41_사용자_방침]]).
- **TRIPO 텍스처 작업은 올린 UV를 쓰지 않고 UV를 새로 편다.** 교복 사무라이 첫 실행과 온천 검사 텍스처 v001(가다듬은 UV 한 층만 올림)에서 루프마다 비교해 확인. 교복 사무라이 상체 재생성에서 "올린 UV를 그대로 칠했다"고 본 것은 조각 수와 넓이만 비교한 판단이었고, TRIPO가 같은 UV를 다시 만든 것을 착각한 것으로 본다(사용자 판단 2026-11-23). 그래서 우리 UV를 쓰려면 받은 그림을 우리 UV로 옮겨 굽는다([[5_텍스처]] 5-4). 받은 파일은 크기와 위치가 정규화돼 돌아온다(되돌리기: (좌표 − translation) ÷ scale).

## 모델 방향 (TRIPO에 올릴 때와 받은 뒤)

- **작업본은 앞이 −y, TRIPO 원본은 앞이 +x다.** 작업본은 가져올 때 TRIPO 원본을 z축 −90도 돌려 만든다(온천 검사 `01_캐릭터/온천_검사/04_Blender/스크립트/가져오기_v001.py`). 상태: 확인(2026-11-24, 온천 검사).
- **TRIPO에 모델을 올릴 때는 늘 `도구/TRIPO입력내보내기.py`로 낸다.** 메모리 안에서만 z축 +90도 돌려 TRIPO 원본 방향으로 내보내고, 발끝이 +x쪽으로 나왔는지 보고 아니면 종료 코드 1로 멈춘다. 작업본은 저장하지 않는다. 받은 것은 `도구/TRIPO받은것되돌리기.py`로 작업본 방향·크기·높이로 되돌린다.
- 근거: 온천 검사 리깅에서 작업본 방향 그대로 올리면 무료 리그 체크가 `riggable: false`, 돌리면 `true`였다. 그림 유무·파츠 수·파일 형식(GLB·FBX)은 결과를 바꾸지 않았다. 옆을 보게 돌린 것(0도)도 `false`. 기록 `01_캐릭터/온천_검사/03_TRIPO/실험_004_오토리깅/02_체크시험/`.
- 텍스처·Smart UV 작업은 작업본 방향 그대로 올려서도 됐다(온천 검사). 앞으로는 이것들도 같은 도구로 원본 방향으로 올린다. 원본 방향으로 올린 텍스처 결과가 같은지는 아직 확인하지 않았다(초안).
- 받은 파일의 정규화: 크기는 `normalize_scale`로 나눈다. 리깅 결과는 발바닥이 z = 0이 되게 올라와 있어(온천 검사 +0.4998) 되돌리기 도구가 작업본의 가장 낮은 z에 맞춰 내린다.
