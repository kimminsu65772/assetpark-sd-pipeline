## 여백 채우기의 원리

- **왜 채우나**: 게임은 캐릭터가 멀어지면 텍스처를 작게 줄인 그림(밉맵)을 쓴다. 줄일 때 조각 밖 빈 칸의 색이 조각 가장자리 색과 섞인다. 빈 칸이 검정이면 멀리서 이음매에 검은 줄이 생긴다. 조각 안 칸은 그대로 두고 밖만 채운다.
- **16칸까지 가장자리 색**: 그림을 1/16(2048 → 128)로 줄여도 조각 가장자리에 닿는 칸의 색이 조각 색만으로 정해진다.
- **그 밖은 조각 둘레 평균**: 더 줄인 그림에서 섞여 들어오는 색이 그 조각의 평균에 가까워 튀지 않는다. 평평한 덩어리라 그림을 열어 볼 때 조각 경계가 잘 보인다.
- **비교(온천 검사, `01_캐릭터/온천_검사/04_Blender/여백비교_v001/`)**: 그림을 128·64·32칸으로 줄여 모델에 입혀 찍음. 128칸에서는 지금(16칸 + 검정)·전체 가장자리 색·16칸 + 평균 셋이 거의 같고(바뀐 화소 칸마다 0~4), 32칸에서 검정은 머리 위와 기모노에 어두운 줄이 생겼다(칸마다 약 3,000~5,000). 전체 가장자리 색과 16칸 + 평균은 32칸에서도 눈으로 구별되지 않았다(칸마다 30~240). 게임 속도는 같다(그림 크기·장수 같음).
- **빠르게 구하는 법**: 16칸까지는 한 칸씩 넓혀 정확히 구한다(16번 반복). 16칸 밖은 "가장 가까운 조각이 어느 것인지"만 알면 되므로, 조각 지도를 1/4로 줄인 격자에서 넓혀 구한다(반복 횟수와 칸 수가 함께 줄어듦). 한 칸씩 끝까지 넓히는 방식(6분 넘게 걸림)과 비교해 다른 칸은 0.25~0.38%, 모두 16칸 밖의 조각 영역 경계이고, 128칸 이하로 줄인 그림에서 조각에 닿는 칸은 같다.

| 손으로 고친 것 | 온천 검사: 눈썹을 손으로 다듬은 단계가 실행 줄로 남지 않아 같은 그림을 다시 만들 수 없었다(독립 검수 지적) | 모든 단계를 한 실행 파일에 넣고, 스크립트로 옮기지 못한 손질은 조각 그림으로 보관해 덮어 쓴다. 두 번 돌려 해시가 같은지 본다 |
| 낡은 그림을 봄 | 비교 그림이 저장되지 않았는데 이전 그림을 보고 판단. 실패한 명령 뒤에 이전 그림을 엶 | 저장 시각을 확인한다. 명령이 끝난 것을 확인한 뒤에 연다 |
| 자세 | 확인 그림이 달리는 자세로 찍힘(작업본의 뼈대에 자세가 들어 있었음) | 찍을 때 기본 자세로 둔다 |
| 스크립트 | 조각 번호가 달라져도 끝까지 돎. 실패해도 종료 코드 0 | 조각 지문을 비교해 다르면 멈춘다. 실패하면 0이 아닌 코드로 끝낸다 |
| 하위 작업자 | 조사 에이전트 6개가 모두 최상위 모델로 돎. 지시문에 없던 방침을 하위 작업자가 지키지 않음 | 모델을 항상 명시. 방침을 지시문에 적고 결과 폴더를 확인 |
| 검수 한도 | 독립 검수가 Codex 사용량 한도로 두 번 멈춤 | 한도가 풀리는 시각을 확인하고, 급하면 다른 Fable에게 |
