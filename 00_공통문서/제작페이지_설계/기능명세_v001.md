# 가마우지 제작 페이지 — 기능 명세 v001

## 한눈에 보기

- **이 문서는 화면의 버튼을 누르면 무슨 일이 일어나는지, 일이 틀어지면 어떻게 하는지, 무엇을 보면 "다 만들었다"고 하는지를 적는다.** 화면 모양은 `화면설계_v001.md`와 `화면초안_v001.html`(그림은 `화면초안_v001_그림/`)에 있다.
- **세 부분으로 나눈다.** 1부 공통(모든 단계가 함께 쓰는 것) → 2부 단계별(1~11단계) → 3부 만드는 작업 묶음(만드는 세션에 넘길 단위와 완료 조건). **세 부분이 모두 있다(3부는 초안).**
- **핵심 규칙 다섯 가지**
  1. 페이지는 고르고 칠하고 보내기만 한다. 고치는 일은 에이전트가 한다. 둘은 **캐릭터 폴더의 파일**로 주고받는다.
  2. 사용자가 보낸 것은 **지워지지 않는다**. 처리된 뒤에도 기록으로 남는다.
  3. 작업본이 바뀌면 그 전에 칠한 표시는 **그 버전에 묶여 있다**. 바뀐 모델 위에 옛 표시를 그대로 얹지 않는다.
  4. 돈이 드는 실행은 승인 상자에 **보낼 값 전체**가 보이고, 그 값 그대로일 때만 실행된다.
  5. 페이지는 **이 PC 밖으로 요청을 보내지 않는다**(TRIPO 실행은 승인 뒤 에이전트나 서버가 하는 일이고, 페이지 화면 자체는 바깥 주소를 부르지 않는다).
- 색·간격·글자 크기·요소 크기·칸 안의 순서는 `디자인규격_v001.md`(값은 `디자인토큰.css`)를 따른다. 그 문서의 완료 조건도 함께 넘어야 한다.
- 값(합격 수치, TRIPO 값 등)은 이 문서에 다시 적지 않고 SSOT 노트를 가리킨다. 한 값은 한 곳에만 적는다.

## 2. 파일 구조

캐릭터 폴더 아래에 페이지 전용 폴더를 둔다. 페이지와 에이전트는 이 폴더만으로 주고받는다.

```text
01_캐릭터/<이름>/제작페이지/
  상태.json                 단계마다 상태, 입력 파일, 출처, 마지막 바뀐 시각
  부위.json                 파츠마다 부위 이름과 면 목록(작업본해시에 묶임)
  보기/                     페이지가 띄우는 파일(작업본에서 서버가 만든 GLB, 그림 사본). 지워도 다시 만든다
  <NN_단계>/
    후보_<시각>.json        에이전트·검사기가 낸 후보와 "고친 것"
    보내기_<시각>.json      사용자가 보낸 묶음(표시 + 후보 판단 + 결정)
    작성중.json             아직 안 보낸 표시(자동 저장)
    처리_<시각>.json        에이전트가 그 묶음을 어떻게 처리했는지(항목마다 고침 / 안 고침 + 이유)
    알림.json               에이전트가 남긴 최신 알림
    승인_<시각>.json        유료 실행 요청(보낼 값 전체)과 사용자의 승인 여부
    되돌리기/<시각>.blend   에이전트가 고치기 직전의 작업본 사본
```

- 파일 이름의 `<시각>`은 `2026-11-24T1530` 꼴. 같은 분에 두 번이면 뒤에 `_2`.
- 모든 JSON에 `작업본해시`(그 파일을 만들 때의 작업본 SHA-256 앞 12자리)를 넣는다. 3절 "버전 묶기"에 쓴다. 파일마다의 항목은 2-1.
- `제작페이지/`의 JSON(후보·보내기·처리·승인·상태·알림)은 git에 넣는다. 어떤 흠을 어떻게 고쳤는지가 기록으로 남고, 자동 검사기 시험의 정답으로도 쓴다. 그림·GLB·blend 사본(`보기/`, `되돌리기/`)은 크기가 커서 넣지 않는다(사용자 결정, 2026-11-24). 기록은 다른 git 기록처럼 사용자 지시가 있을 때 한다.

### 2-1. 파일 꼴 (페이지와 에이전트의 약속)

**쉬운 요약**: 페이지와 에이전트가 주고받는 파일마다 어떤 항목이 어떤 모양으로 들어가는지 정한 표다. 페이지를 만드는 세션과 에이전트 쪽을 만드는 세션이 이 표 하나를 보고 맞춘다. 항목 이름은 한국어 그대로 쓴다.

공통 규칙:
- 모든 JSON 파일은 UTF-8이고, 맨 위에 `꼴버전`(지금 1), `만든시각`(`2026-11-24T15:30:00+09:00` 꼴), `작업본해시`(앞 12자리, 작업본이 없는 단계는 빈 글)를 둔다.
- 꼴을 바꾸면 `꼴버전`을 올리고 이 표를 고친다. 모르는 항목은 지우지 않고 그대로 둔다(읽는 쪽이 무시).
- 시각은 모두 한국 시각(+09:00).

## 3. 페이지와 에이전트가 주고받는 흐름

### 3-1. 한 번 고치는 흐름

```text
에이전트: 훑기 → 후보_<시각>.json, 알림.json 쓰기 → 상태 "결정 대기"
사용자:  페이지에서 후보 판단, 직접 칠하기(작성중.json에 자동 저장)
사용자:  "보내기" → 보내기_<시각>.json → 상태 "보냄"
사용자:  Claude 앱에서 "보냈어"
에이전트: 가장 최근 "보냄" 묶음을 읽음 → 되돌리기 사본 저장 → 고침
         → 처리_<시각>.json, 알림.json 쓰기 → 보기/ 다시 만들기 → 상태 "결정 대기"
사용자:  페이지에서 전후 확인 → 또 보내기 / "이 단계 끝" / "되돌리기"
```

### 3-1b. 언제 멈추고 묻나 (모든 단계 공통, 사용자 2026-11-24)

- **뒤의 작업이 기대는 결정은 그 작업 앞에서 한 번 묻는다.** 끝에서 바꾸면 앞의 일을 다시 해야 하는 결정이다(예: 대칭 기준 쪽).
- **뒤의 작업이 기대지 않는 결정은 끝에서 모아 한 번에 묻는다**(예: 지울 조각, 고칠 흠).
- 그 사이에는 묻지 않고 진행한다. 한 단계에서 멈추는 곳은 이 두 종류뿐이다. 단계마다 멈추는 곳은 2부에 적는다.
- 끝에서 사용자의 답이 앞의 결정을 뒤집게 되면(구조가 잘못된 것), 에이전트는 그 결정을 "앞에서 물을 결정"으로 옮기도록 명세를 고치자고 보고한다.

### 3-2. 보내기 묶음의 상태

| 상태 | 뜻 | 페이지에 보이는 것 |
| --- | --- | --- |
| 작성 중 | 칠하는 중, 안 보냄 | 표시 목록, "표시 N개 보내기" 버튼 |
| 보냄 | 파일로 저장됨, 에이전트가 아직 안 읽음 | "보냄 — Claude 앱에서 '보냈어'라고 알려 주세요" |
| 처리 중 | 에이전트가 읽고 고치는 중(에이전트가 상태를 바꿈) | "처리 중", 칠하기 막힘 |
| 처리됨 | `처리_<시각>.json`이 있음 | 항목마다 고침 / 안 고침 + 이유, 전후 보기 |
| 실패 | 에이전트가 끝내지 못함 | 알림에 이유. 묶음은 다시 보낼 수 있음 |

### 3-3. 버전 묶기

- 표시는 칠할 때의 작업본에 묶인다(`작업본해시`).
- 페이지를 열거나 새로 고칠 때 작업본이 바뀌었으면, **작성 중인 표시는 "옛 버전" 표시로 바뀐다**(회색, 점선). 지워지지는 않는다. 사용자는 새 모델에 다시 칠하거나, 옛 표시를 그대로 보낼 수 있다(에이전트는 옛 버전임을 보고 자리를 다시 찾는다. 못 찾으면 "안 고침: 자리를 못 찾음").
- 면 번호는 작업본의 면 번호다. 서버가 GLB를 만들 때 면마다 원래 번호를 함께 넣는다(GLB는 면을 나누거나 정점을 쪼갤 수 있어서다).

### 4-6. 화면 크기와 글 넘침

예전에 스크롤이 없어 글이 칸 밖으로 넘친 일이 있었다(사용자). 그래서 아래를 지킨다.

- **칸마다 따로 스크롤된다.** 왼쪽 단계 목록, 가운데 작업 칸, 오른쪽 결정 칸, 표시 목록은 내용이 넘치면 그 칸 안에서만 세로 스크롤이 생긴다. 페이지 전체가 가로로 밀리지 않는다. 윗줄은 늘 보인다.
- **글은 칸 안에서 줄을 바꾼다.** 긴 파일 경로·명령 값처럼 끊기 어려운 글은 줄 바꿈하고, 한 줄로 둬야 하는 곳(표시 목록의 자리 설명 등)은 말줄임(…)을 쓰고 마우스를 올리면 전체를 보여 준다. 어떤 글도 칸의 테두리 밖으로 나가지 않는다.
- **3D 보기와 UV 그림은 칸 크기에 맞춰 커지고 줄어든다.** 비율은 유지한다.
- **기준 화면은 1920×1080**(사용자). 다음에서도 넘침 없이 쓸 수 있어야 한다: 브라우저 확대 125%·150%(Windows 배율 125%면 실제 폭은 1536), 창을 1280×720까지 줄였을 때. 그보다 작으면 오른쪽 결정 칸을 접을 수 있게 하고(접어도 "보내기"는 윗줄에 남음), 넘침 대신 스크롤로 처리한다.
- 한국어 글꼴은 PC에 있는 맑은 고딕을 쓴다(바깥에서 불러오지 않음).

### 5-2b. 부위 목록 만들기

- **누가**: 에이전트가 만든다. 사용자가 손으로 고르지 않는다.
- **어떻게**: 파츠마다 서로 이어진 덩어리, UV 조각(텍스처 단계의 조각 지도 `SSOT/도구/텍스처/조각지도.py`), 자리(위아래·좌우·앞뒤)로 면을 묶고 이름을 붙인다. 좌우는 1부 규칙대로 쓴다(모델의 자리는 화면을 보는 사람 기준, 오른쪽 = +x).
- **언제**: 3단계에서 파츠를 나눈 뒤 처음 만들고, 면이 바뀌는 단계(리토폴로지, UV) 뒤에 다시 만든다. `부위.json`의 작업본해시가 지금 작업본과 다르면 목록을 회색으로 두고 "부위 목록이 옛 것" 표시.
- **고치기**: 이름이 틀렸거나 묶음이 이상하면 목록에서 이름을 바꿀 수 있다(바꾼 이름은 다시 만들 때도 같은 자리면 이어받음). 묶음 자체가 틀렸으면 Claude 앱에서 말한다.
- **확인하지 않은 것**: 자동으로 붙인 이름이 얼마나 맞는지는 해 보지 않았다. 세 번째 캐릭터에서 처음 확인한다.

### 5-3. UV 그림 나란히 (텍스처가 있는 단계)

- 오른쪽에 지금 파츠의 UV 그림(텍스처를 입힌 것). 파츠는 마우스가 올라간 모델의 파츠를 따라 바뀌고, 고정할 수도 있다.
- 모델 위 마우스 자리 → UV 그림에 십자. UV 그림 위 마우스 자리 → 모델의 같은 자리에 점(그 UV 자리를 쓰는 면이 여럿이면 모두).
- UV 그림 위에서도 칠할 수 있다. 칠한 화소를 쓰는 면이 표시에 함께 들어간다.

### 5-4. 칠하기

| 요소 | 동작 | 예외 |
| --- | --- | --- |
| 처리 고르기 | 단계마다 다름(2부). 메시: 지우기 / 메우기 / 매끈하게 / 모양이 이상함. 텍스처: (2부에서 정함) | 고르지 않고 칠하면 "모양이 이상함"(판단은 에이전트) |
| 붓 | 누르고 끌면 닿은 면이 칠해진다. 붓 크기는 화면 픽셀로 정하고 Shift+휠로 바꾼다. 손을 떼면 표시 하나가 생긴다(①②… 번호) | 모델 밖을 칠하면 무시. 한 번 누름(끌지 않음)은 그 면 하나 |
| 이어 칠하기 | 같은 번호에 더 칠하려면 표시 목록에서 그 번호를 고른 뒤 칠한다 | — |
| 지우개 | 칠한 면을 뺀다. 표시의 면이 0이 되면 표시가 지워진다 | — |
| 취소 / 다시 | Ctrl+Z로 취소, Ctrl+Y(또는 Ctrl+Shift+Z)로 다시. 취소되는 것: 칠하기, 지우개, 표시 지우기, 처리 종류·후보 판단 바꾸기, 메모, 반대쪽도 켜고 끄기. 취소되지 않는 것: 카메라 움직임, 보내기(보낸 묶음은 남는다. 고칠 것이 있으면 새로 보낸다), 에이전트가 고친 것(그건 "되돌리기" 버튼). 기록은 단계마다 따로, 창을 닫았다 열어도 마지막 50번(제안값)까지 남는다 | 보낸 뒤에는 보내기 전 동작까지 거슬러 취소하지 않는다(취소 기록이 보내기에서 끊긴다) |
| 메모 | 표시 목록의 줄을 누르면 짧은 글을 적을 수 있다(선택) | — |
| 반대쪽도 | 표시마다 켤 수 있다(기본 꺼짐). 켜면 에이전트가 좌우 대칭 자리도 같이 고친다(방침 "한쪽만 고치고 뒤집기") | 비대칭 예외 부위(SSOT `41_사용자_방침` "비대칭 예외", 눈의 반사점 포함)면 켤 수 없고 이유를 보인다 |
| 자동 저장 | 칠할 때마다 `작성중.json`에 저장. 창을 닫아도 남는다 | 저장 실패 → 빨간 경고, 칠하기를 막지는 않음 |

모든 목록의 끝은 "기타"다. 기타를 고르면 메모가 반드시 필요하다(빈 메모로는 보낼 수 없다).

| 6 Smart UV | 3D·UV 위 | 늘어남·찌그러짐 / 기타 |

## 7. 에이전트 쪽 약속

페이지를 쓰는 단계에서 에이전트(만드는 세션 포함)가 지킬 것.

1. "보냈어"를 들으면 그 단계의 가장 최근 "보냄" 묶음을 읽는다. 상태를 "처리 중"으로 바꾼다.
2. 작업본을 바꾸기 전에 `되돌리기/<시각>.blend`를 만든다.
3. 묶음의 **모든 항목**에 대해 고침 / 안 고침 + 이유를 `처리_<시각>.json`에 쓴다. 빠뜨린 항목이 있으면 처리됨으로 바꾸지 않는다.
4. 고친 뒤 SSOT `40_검수와_보고` 4절의 점검을 하고, 알림에 "열어 본 그림 / 만들기만 한 그림"을 구분해 적는다.
5. 표시의 작업본해시가 지금 작업본과 다르면 자리를 다시 찾고, 못 찾으면 "안 고침: 자리를 못 찾음"으로 적는다.
6. 페이지가 쓰는 파일(`작성중.json`, `보내기_*.json`, `승인_*.json`)은 읽기만 한다. 상태 바꾸기와 "실행됨" 표시만 예외.

### 7-1. 에이전트가 쓰는 명령

**쉬운 요약**: 사용자가 Claude 앱에서 "보냈어"라고 하면 에이전트가 부르는 명령이다. 파일을 손으로 고치지 않고 이 명령으로만 읽고 쓰게 해서, 항목을 빠뜨리거나 꼴이 어긋나는 일을 막는다. W06에서 만든다.

꼴: `python 10_제작페이지/에이전트.py <명령> --캐릭터 <이름> --단계 <번호> [인자]`. 결과는 JSON 한 덩어리로 출력한다. 잘못되면 종료 코드 1과 이유.

| 명령 | 하는 일 |
| --- | --- |
| `받기` | 그 단계의 가장 오래된 "보냄" 묶음을 읽어 요약과 경로를 출력하고, 묶음 상태를 "처리 중"으로, 단계 상태를 "진행 중"으로 바꾼다. 보낸 것이 없으면 "없음" |
| `사본` | 작업본을 `되돌리기/<시각>.blend`로 복사하고 경로를 출력. 사본 10개가 넘으면 지울 후보를 출력만 함(지우지 않음) |
| `후보 <파일.json>` | 후보·고친 것을 2-1 꼴로 검사해 `후보_<시각>.json`으로 쓰고, 단계 상태를 "결정 대기"로 |
| `처리 <묶음> <파일.json>` | 처리 결과를 검사해(모든 항목에 결과가 있는지, 안 고침에 이유, 고침에 근거그림) `처리_<시각>.json`으로 쓰고 묶음을 "처리됨"으로. 빠진 것이 있으면 쓰지 않고 거부 |
| `실패 <묶음> "<이유>"` | 묶음을 "실패"로, 단계 상태를 "막힘"으로, 알림에 이유 |
| `알림 "<글>" [--종류 안내/결정 필요/막힘]` | 알림 쓰기(지난 알림은 기록으로) |
| `상태 <상태>` | 단계 상태 바꾸기("끝"은 거부 — 사용자가 페이지에서만 누름) |
| `보기갱신` | 3D 보기 파일을 다시 만들게 서버에 알림(작업본을 바꾼 뒤) |
| `부위 <파일.json>` | 부위 목록 쓰기(사용자가 바꾼 이름 이어받기) |

- 이 명령의 쓰는 법은 스킬 문서와 `10_제작페이지/에이전트_안내.md`에 둔다. 에이전트는 페이지 일을 시작할 때 그 안내를 읽는다.

## 9. 1부의 완료 조건 (공통 부분을 다 만들었다고 볼 때)

아래는 **새 캐릭터(세 번째 캐릭터)를 이 페이지로 만들면서** 확인한다(사용자 결정, 2026-11-24). 교복 사무라이·온천 검사로 확인하지 않는다. 페이지를 시험하는 일과 세 번째 캐릭터로 파이프라인을 반복하는 일을 한 번에 한다.

- 항목마다 그 일이 처음 일어나는 단계에서 확인한다: 1~3번은 시작할 때(새 캐릭터 만들기), 4~8번은 모델이 생긴 뒤(텍스처가 필요한 5번은 5단계 텍스처 생성 뒤), 9번은 첫 유료 단계 전, 10번은 첫 수정 단계, 11·12번은 언제든(12번은 단계 화면이 생길 때마다 다시).
- 만드는 세션은 확인한 항목과 열어 본 화면 그림을 그때그때 보고한다. 아직 그 단계에 이르지 않은 항목은 "확인 전"으로 적는다.
- 새 캐릭터의 컨셉(헤어·의상 등)은 사용자에게 받는다. 받기 전에는 1단계를 시작하지 않는다.
- 유료 실행(TRIPO)이 실제로 일어난다. 평소처럼 승인 상자의 값과 크레딧을 보고 승인한다.

1. `.bat` 두 번 클릭과 명령 한 줄로 켜지고, 주소가 `127.0.0.1`이다. 같은 와이파이의 다른 기기에서 열리지 않는다.
2. 페이지를 연 동안 브라우저 개발자 도구의 네트워크 기록에 `127.0.0.1` 말고는 요청이 없다.
3. 캐릭터를 바꾸면 단계 목록과 상태가 그 캐릭터 것으로 바뀐다. `상태.json`이 없는 캐릭터는 "새 캐릭터로 만들기"를 묻는다.
4. 작업본에서 GLB가 만들어지고, 모든 파츠가(텍스처가 있으면 텍스처와 함께) 뜬다. 앞·옆·뒤·아래 버튼, 파츠 숨김, 형태만, 격자가 동작한다.
5. 모델 위 마우스 자리와 UV 그림의 십자가 같은 자리다(파츠 모두, 일부러 고른 다섯 곳 이상을 Blender의 같은 면과 대조).
6. 칠한 표시의 면 번호가 작업본의 면 번호와 같다(Blender에서 그 면들을 골라 그림으로 확인).
7. 칠하고 창을 닫았다 열어도 표시가 남는다. 보내기를 누르면 `보내기_<시각>.json`이 생기고, 모든 표시·판단이 들어 있다.
8. 작업본을 바꾸면 작성 중 표시가 "옛 버전"으로 바뀌고 지워지지 않는다.
9. 승인 상자의 값을 바꾸면 그 전 승인이 무효가 된다. 같은 승인으로 두 번 실행되지 않는다(가짜 실행으로 시험, 돈 쓰지 않음).
10. 되돌리기로 작업본이 고른 사본으로 바뀌고, 바꾸기 전 작업본도 사본으로 남는다.
11. 8절의 예외 가운데 "서버가 꺼짐", "여러 탭", "포트가 쓰이는 중"을 일부러 일으켜 정해진 대로 동작한다.
12. 1920×1080, 1536×864(배율 125%), 1280×720에서 모든 단계 화면을 열어, 칸 밖으로 나간 글과 페이지 가로 스크롤이 없다(브라우저에서 넘친 요소를 자동으로 세는 검사 + 단계마다 화면 그림). 긴 경로·긴 메모·표시 100개를 넣은 상태로도 확인한다.

  2. 완료 조건마다: 통과 / 실패 / 확인 전 + 근거(열어 본 화면 그림, 검사 출력)
  3. 열어 본 그림 / 만들기만 한 그림 구분
  4. 시안과 나란히 놓은 그림(화면이 있는 묶음)
  5. 검수: 아래 "맡는 모델과 검사" 표대로 한 결과와 반영. Codex Astra는 쓰지 않는다(Astra 검수는 모델 결과물용). 받지 못한 검수는 "받지 않음"
- **시험 자료**: 만드는 동안에는 **온천 검사 작업본의 사본**을 쓴다(원본은 건드리지 않음). 완료로 인정하는 확인은 1부 9절대로 **세 번째 캐릭터**로 한다. 그래서 묶음마다 "만드는 동안 통과"와 "세 번째 캐릭터로 통과"를 따로 적는다.
- **돈**: 만드는 동안 TRIPO 실행은 가짜 실행(서버가 받은 값을 그대로 돌려주는 흉내)으로 한다. 진짜 실행은 세 번째 캐릭터에서 사용자가 승인할 때뿐이다.
- **git**: 묶음마다 끝나면 기록할지 사용자에게 묻는다(사용자 지시가 있을 때만 기록, 바꾼 파일만).
